# I-041 · The QR carries the room code; the bare URL asks for it — the owner's request (shipped)

Spec: `C:\dev\partybox-ideas\specs\I-041.md` (a KEEP with a request: "add a code field when
someone goes to 192.168.4.87:42069 … If they scan the QR code then it should automatically take
them to the room without needing to enter the code").

- `/api/info` gains `qrUrl` = `joinUrl` + `?room=<house code>`; the TV's QR encodes it, the URL
  the TV prints stays bare.
- The join form reads `room` from the page URL: present → the code is filled and hidden and
  "Joining room KPFT" sits above the name; absent → the room-code field always shows
  ("4 letters from the TV"), and a wrong code shakes THAT field with its own error line (the
  name stays clean). `needsCode` is "no code in the URL", not "room count ≠ 1".
- The server's `resolveRoom` fallback for a code-less join is unchanged.
- The design harness: `openPhone` opens the QR's URL by default (`{ bare: true }` for the typed
  one) and `joinViaForm` types the house code into a visible field — every capture script keeps
  working.
