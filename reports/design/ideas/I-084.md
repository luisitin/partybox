# I-084 · The first paint is the app, not a white flash (option C)

Branch `b/I-084-C` cherry-picked clean — one file, `packages/client/index.html`.

## What ships

- **A** — an inline `<style>` paints `#0f1020` / `#f3f4ff` before any JS: a few bytes, no request.
- **B** — a tiny inline script reads `partybox:theme` and sets `data-theme` on `<html>` before the
  first paint, and the five themes' backgrounds sit in that same inline style — so a remembered
  theme never flashes through the default either. All five match `tokens.css` (`#0f1020`,
  `#f6f5ff`, `#050014`, `#1d1410`, `#000000`) — checked against the live tokens, not the branch.
- **C** — `#root:empty::before` shows a centred pink "PB" until the app mounts.

## Proof

Scratchpad `c-capture/probe_I084.ts` holds every script for 3 s and reads the page **before the
bundle runs**:

```
theme=default   {"html":"rgb(15, 16, 32)",   "body":"rgb(15, 16, 32)",   "theme":"none",     "rootEmpty":true,"mark":"\"PB\""}
theme=daylight  {"html":"rgb(246, 245, 255)","body":"rgb(246, 245, 255)","theme":"daylight", "rootEmpty":true,"mark":"\"PB\""}
theme=arcade    {"html":"rgb(5, 0, 20)",     "body":"rgb(5, 0, 20)",     "theme":"arcade",   "rootEmpty":true,"mark":"\"PB\""}
```

The theme attribute and its exact background are already on the document with `#root` still empty,
and the PB mark is rendered. `pnpm verify` GREEN.
