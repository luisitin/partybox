# I-103 · Bingo's Points board climbs (option B)

Branch `b/I-103-B` cherry-picked clean — one file, `games/bingo/client/Tv.tsx`. That file was then
over the 300-line cap, so `climbFrom`, `joinNames` and the dibs cue moved to a new
`games/bingo/client/tvBoard.ts`; the probes were re-run after the split and read the same.

## What ships

- **A** — the board is `stagger="climb"` with `climbFrom` = the order before this round's points
  (pre-delta wins, ties in roster order — the I-027 rule Wisecrack already uses), so a rank change
  is the visible consequence of the points.
- **B** — ranks show `·` and totals `—` for one beat (`holdMs={600}`) before the count-up: nothing
  is ranked until the numbers move.

## Proof

Two probes (scratchpad `c-capture/probe_I103.ts`, `probe_I103b.ts`), sampling the board every
animation frame from page start — text plus each row's translateY.

The hold and the count-up, on the real TV (dev-loaded scoreboard, Player 1 wins the round 3–0):

```
 310ms  ·Player 2—  | ·Player 1+3— | ·Player 3— | ·Player 4—      ← ranks ·, totals —
 925ms  1Player 2 0 | 2Player 1+3 0 …                             ← ranks land, count starts at 0
1226ms  1Player 1+3 3 | 2Player 2+2 2 …                            ← counted up
```

The climb, with a real rank change (Player 2 led 5–0, Player 1 wins the round 6–0 and overtakes):

```
1004ms  1Player 1+6 2 @ +98px | 2Player 2 2 @ −98px   ← the leader's row still sits where it stood
1255ms  1Player 1+6 5 @ +98px | 2Player 2 5 @ −98px   ← numbers counting, rows still in old places
1589ms  1Player 1+6 6 @ +46px | 2Player 2 5 @ −46px   ← the climb runs as the count finishes
2121ms  1Player 1+6 6 @   0px | 2Player 2 5 @   0px   ← landed in the new order
```

98 px is exactly one row: the board ranks Player 1 first only after his points have counted in.
`pnpm verify` GREEN.
