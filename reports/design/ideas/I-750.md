# I-750 · Bingo (server) · send only what changed — shipped option C

Cherry-picked `b/I-750-C` (b35b09c0) cleanly: `host.ts` keeps the last room snapshot and view sent to
each phone and the last snapshot sent to a room's TVs and skips an identical push (A; a welcome or
`resend` forgets the phone's entries); `sockets.ts` holds a busy connection's `room`/`view` pushes and
sends only the newest of each when it frees up (B); Socket.IO deflates messages over 1 KB (C).
`push-dedupe.test.ts` (an unchanged room is not re-sent) passes. Documented in docs/PROTOCOL.md under
`rev` ordering and in the Bingo README.

## Proof (probe on this worktree, port 42181)

16 players: Priya and Sam on real phones, 14 `slow` bots daubing, `callSeconds` 3; Sam's phone
throttled to 1 Mbps / 80 ms through CDP. Measured over 20 s of play (after an 8 s intro):

| phone        | received  | messages |
| ------------ | --------- | -------- |
| Priya        | 1.46 KB/s | 8        |
| Sam (1 Mbps) | 1.70 KB/s | 9        |

Session B's baseline on main (same room shape): 132 KB/s, 359 messages in 30 s. Sam's phone stayed
level with the server the whole time: server call 3 / 5 / 7 / 8 at 5 / 10 / 15 / 20 s, the phone
read "call 3 / 5 / 7 / 8" at the same samples (main fell 25→150 updates behind under the same limit).
Nothing visible changes by design.
