# SDK / contract requests from the design session

Things a design needed that `docs/GAME_CONTRACT.md` or `@partybox/game-sdk` cannot do yet. One entry per
gap, newest last; the owner decides what becomes an ADR or a backlog item. Status: open / accepted / done.

| #   | Requested by      | Gap                                                                                                                                                                                                                                                                                                             | Proposed shape                                                                                                                                                                                                                                                                            | Status |
| --- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| R-1 | 001 Bingo         | **Quiet timer mode.** Both shells' `Timer` turns red, scales 1.1× and plays `countdown` in the last 5 s of _every_ deadline. A game whose phase re-enters itself every 6 s (bingo calls) would tick five of every six seconds forever.                                                                          | Optional envelope field `timer?: 'normal' \| 'quiet' \| 'hidden'` (default `normal`) honoured by `TvPlaying` and the controller shell. Contract change → ADR. Interim heuristic: suppress urgency when the phase is shorter than 15 s (needs `startedAt` in the envelope, also a change). | open   |
| R-2 | 001 Bingo         | **Game-triggered sound cues.** `GameClientModule.sounds` maps moments to cue names, but `GameTvProps` / `GameControllerProps` give a game no way to _play_ one; `TvPlaying` keeps `audio` to itself. Any game with an in-phase event (a new call, a bogus claim, a reveal step) has no sound.                   | `useSound(): (moment: string) => void` exported from `@partybox/game-sdk/ui`, backed by a context both shells provide; resolves `moment` through `clientModule.sounds` and no-ops for unknown moments.                                                                                    | open   |
| R-3 | 001 Bingo         | **A negative chip status.** `PlayerStatus` is `active \| submitted \| waiting \| spectator`; there is no glyph for "penalised / locked out". Bingo reuses `waiting` for a locked player, which reads as "idle".                                                                                                 | Add `'penalty'` (glyph ✕, danger outline) to `PlayerStatus`. Small contract change.                                                                                                                                                                                                       | open   |
| R-4 | 002 Broken Pencil | **A shared drawing surface.** BL-002 expects a drawing game, but there is no canvas, toolbar, ink-budget or stroke renderer in `@partybox/game-sdk/ui`, and no stroke encoding in `@partybox/game-sdk`. Every drawing game would re-implement ~500 lines of pointer capture, simplification and base64 packing. | `DrawPad` (pointer capture → quantised 256² points → RDP simplification → base64 strokes, undo, ink meter) + `DrawingView` (SVG renderer with optional replay) in `ui`; `encodeStrokes/decodeStrokes` in the pure surface. Build inside `games/broken-pencil` first, lift after review.   | open   |
| R-5 | 002 Broken Pencil | **Do spectator inputs reach `reduce`?** The design lets late joiners vote. `docs/PROTOCOL.md` validates inputs against `inputSchema` but does not say whether inputs from sockets that are not in `state.players` are forwarded or dropped.                                                                     | Document the behaviour in PROTOCOL.md; if dropped, add an opt-in manifest flag `acceptSpectatorInputs`.                                                                                                                                                                                   | open   |
